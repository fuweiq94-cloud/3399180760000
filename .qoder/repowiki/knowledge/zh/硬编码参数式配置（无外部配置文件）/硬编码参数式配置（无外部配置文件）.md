## 1. 使用的系统/方法

本仓库**没有实现任何独立的配置系统**。所有运行时参数均以 Python 源码中的字面量或函数默认参数的形式硬编码在模块内，不存在 `config/`、`.yaml`、`.env`、`.toml`、`.json`、`argparse`、`os.environ` 等任何形式的集中式配置加载机制。

## 2. 关键文件与位置

- **训练入口 `train.py`**：`Trainer.__init__` 的默认参数 `n_episodes=10000, max_steps_per_episode=500, log_interval=10, save_interval=50`；`main()` 中再次以关键字参数覆盖为 `n_episodes=5000`。环境网格大小通过 `SnakeEnv(grid_size=20)` 硬编码传入。
- **智能体 `d3qn_agent.py`**：`D3QNAgent.__init__` 内置全部超参——`gamma=0.99`、`epsilon_start=1.0`、`epsilon_end=0.05`、`epsilon_decay=0.995`、`batch_size=64`、`buffer_size=100000`、`target_update=1000`、`lr=1e-4`、`input_dim=9`、`num_actions=4`、设备选择 `device='cuda' if torch.cuda.is_available() else 'cpu'`。
- **演示脚本 `demo.py`**：模型路径 `'models/d3qn_snake_episode_5000.pth'` 写死；`grid_size=20` 同样硬编码。
- **环境 `snake_env.py`**：`SnakeEnv.__init__(self, grid_size=20, observation_type='vision')` 提供默认值，但调用方几乎总是使用默认。
- **网络 `d3qn_network.py`**：网络结构参数（如 `fc1_dim`、`fc2_dim`）仅在 `demo.py` 的 `compare_architectures` 中以字典传参方式临时使用，并非持久化配置。

## 3. 架构与约定

- **参数即代码**：所有可调超参都位于类构造函数的签名或函数体内，修改配置必须直接编辑 Python 源码。
- **分层默认值**：`snake_env.py` 提供 `grid_size=20` 作为环境级默认；`train.py` 和 `demo.py` 再各自覆盖一次，形成“环境默认 → 训练/演示覆盖”的两层硬编码。
- **设备自动选择**：唯一接近“运行时配置”的逻辑是 `device='cuda' if torch.cuda.is_available() else 'cpu'`，根据 GPU 可用性动态决定运行设备。
- **模型持久化约定**：训练产出统一写入 `models/` 目录，文件名格式固定为 `d3qn_snake_episode_{episode}.pth`，由 `save_trained_model` 生成；演示脚本期望该命名约定来加载模型。
- **日志/指标输出**：训练状态通过 `print` 输出到 stdout，图表保存为根目录下的 `training_curves.png`，无结构化日志文件或配置项控制输出级别。

## 4. 约定与约束

- **无外部配置文件**：仓库中不存在任何 `.yaml`、`.json`、`.toml`、`.env`、`.cfg`、`.ini` 等配置文件，也没有读取 `os.environ` 或命令行参数的逻辑。
- **修改行为需改源码**：调整学习率、探索率、批次大小、网格尺寸、训练轮数等任何运行时行为，都必须直接修改对应 Python 源文件中的常量或函数默认参数。
- **模型路径约定**：`models/` 目录由 `os.makedirs('models', exist_ok=True)` 自动创建；已训练模型按 `episode` 编号命名，演示脚本依赖该命名约定进行加载。
- **渲染开关**：是否渲染游戏画面由 `train_one_episode(render=False/True)` 的布尔参数控制，属于调用方约定的运行时开关，而非配置项。
- **收敛判定硬编码**：当最近 100 轮平均奖励超过 `50.0` 时训练提前终止，该阈值写在 `train.py` 中，不可通过外部配置调整。

总结：这是一个典型的“零配置”小项目，所有行为通过 Python 源码中的硬编码默认值和函数参数表达，适合快速实验与教学演示，但不支持部署时的外部化配置管理。
